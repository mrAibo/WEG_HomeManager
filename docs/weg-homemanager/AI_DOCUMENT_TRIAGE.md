# E10 — Model-agnostic AI Document Understanding (synthetic-only)

**User intent:** The WEG user should not have to classify a PDF/photo beforehand; the chosen AI should recognize the document, explain what it is, identify source-backed details and recommend the next steps. A generic document is an *inbox work item*, not an automatic order, payment, agenda item or legal conclusion.

## End-to-end workflow
1. On the redesigned Dashboard select PDF/JPG/PNG and click **Dokument jetzt ablegen**. This stores the **original immutable Evidence** in a permanent Case. The selection is not an OCR or AI upload.
2. Open the saved Case. Choose **Dokument mit KI analysieren**, explicitly checking permission to send the full file to the **tenant-selected model/provider**. Without configured provider or this explicit approval, there is no external call. Local models may be selected through compatible endpoint settings if they genuinely support vision/PDF.
3. **One model call** transcribes the document and proposes `triage`: one whitelisted class (invoice, payment reminder, contract, owner request, meeting proposal/minutes/invitation, insurance, technical report, government notice, etc.), self-estimated confidence, short explanation, issuer/WEG hints, optional explicit dates, up to 8 facts with exact quotes from transcription, and 1–5 suggestions with urgency hints.
4. The UI shows **KI-Einschätzung** above editable OCR. Suggested action links only navigate to the relevant existing module, they NEVER execute a command. Labels and hrefs are whitelisted in source; arbitrary model-supplied URLs, code or business operations fail schema validation. Potential due dates, financial details, actor identity and WEG are expressly **unverified suggestions**. No automatic filing into Documents, dispatch, bookkeeping, invitations, contractor orders, payments or agenda creation.
5. Existing manual OCR review edits the text. `triage` stays bound to original via Evidence SHA-256, with warning that it can be stale after text correction. Existing older recognitions have `triage=null` and continue displaying the OCR editor.

## Technical contract / safeguards
- `src/lib/ai-document-triage.ts`: strict Zod allowed categories, action identifiers, confidence range, optional dates and explicit byte-bounded facts. Each evidence quote must occur **verbatim** within the literal text. Strict parser rejects extras like `sendMoney`, `SEND_EMAIL`, fabricated quotes and malformed data. No arbitrary model-supplied link is used.
- `src/lib/ai-document-recognition.ts`: shared provider abstraction (OpenAI-compatible image Chat Completions, OpenAI Responses PDF, Anthropic vision/PDF). Prompt requests combined OCR and triage **once**, warns about prompt injection. No separate OCR server, fixed heavy model, or silent model fallback. `triage` is optional to retain backward compatibility with providers/models returning the old valid transcription contract. No classification is claimed in this case.
- `src/server/ai-recognition-workflow.ts`: unmodified tenant actor/RBAC, document integrity recheck, explicit consent, DRAFT lock and single-record audit. Strictly validates triage *again* on the server before persisting, even for injected test recognizers. No AI-origin user/business edits.
- Additive migration `20261023103000_recognition_triage`: nullable `AiRecognition.triage Json?`; previous recognitions unchanged. **68** synthetic Postgres migrations.
- UI `src/components/case-recognition.tsx`: displays category, optional issuer/WEG/assumed due date, facts with OCR evidence, human-check list and links to sections. Does not mistake model confidence for a calibrated probability.
- **Not a malware scanner.** Existing file intake validation and OS antivirus policy remain separate. Restrict real documents until production GDPR/security checks; never send user's private WEG PDFs to external AI without explicit user approval.
- Existing `src/lib/ai-document-recognition.test.ts`, `src/lib/ai-document-triage.test.ts`, `scripts/e7-recognition-db-smoke.ts`, `scripts/e7-recognition-ui-smoke.mjs` cover one-call result, rejected model instructions and ungrounded evidence, persistent JSON, human review, no changes to proposal, local mock-only provider. All scripts use synthetic local WEG tenant.
